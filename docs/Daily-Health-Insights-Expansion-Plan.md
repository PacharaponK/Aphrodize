# แผนเพิ่มการตีความสุขภาพผิวและผลพยากรณ์สุขภาพรายวัน

**สถานะ:** เริ่ม implementation ตามแผน — dashboard/การตีความ, consent-gated profile context, self-report outcome collection และ OOD status ถูกเชื่อมแล้ว; ยังไม่ฝึกโมเดลพยากรณ์วันถัดไปเพราะต้องรอ label จริง  
**วันที่:** 26 กันยายน 2026

## 1. เป้าหมาย

หน้า `/clients` ปัจจุบันแสดงคะแนน `thirst` และ `skin_dryness` จากโมเดลรายวัน ผู้ใช้ต้องการให้เข้าใจผลเหล่านี้เป็นภาพรวมมากขึ้น และเพิ่มผลด้านสุขภาพอีก 2 รายการ

แผนนี้แยกงานเป็น 2 ชนิด เพื่อไม่ให้การตีความคะแนนเดิมถูกเข้าใจว่าเป็นผลทำนายทางการแพทย์:

1. เพิ่ม **สัญญาณที่ควรใส่ใจ 3 ระดับ: ต่ำ / กลาง / สูง** พร้อมบอกข้อสังเกตที่อาจพบและคำแนะนำสั้น ๆ จาก thirst/dryness ที่มีอยู่แล้ว (กฎ ไม่ใช่โมเดลเพิ่ม)
2. เพิ่มผลพยากรณ์รายวัน 2 รายการ โดยเก็บผลจริงที่ผู้ใช้รายงานก่อนฝึกโมเดล

## 2. ข้อเสนอ: สัญญาณที่ควรใส่ใจจาก thirst + dryness

ใช้ชื่อแสดงผล **“ระดับสัญญาณที่ควรใส่ใจ”** (`skin_care_attention_level`) และมีระดับเมื่อประเมินได้เพียง 3 ระดับ: **ต่ำ / กลาง / สูง** คำว่า “เสี่ยง” ใน UI ต้องสื่อเป็นสัญญาณจากข้อมูลที่กรอก ไม่ใช่โอกาสเป็นโรคหรือคำวินิจฉัย ส่วน `not_available` เป็นสถานะข้อมูล ไม่ใช่ระดับที่ 4; เมื่อข้อมูลไม่พอให้แสดง “ประเมินไม่ได้” แทนการเดาระดับ

### กฎเริ่มต้นสำหรับต้นแบบ

กำหนด `T` = thirst score และ `D` = dryness score ซึ่งมีช่วง 0–10:

| ระดับ | กฎชั่วคราว | ข้อความ/คำแนะนำสั้น ๆ ที่อาจแสดง |
| --- | --- | --- |
| ต่ำ | `D < 4` และ `T < 4` | “รอบนี้ไม่มีสัญญาณเด่นจากข้อมูลที่กรอก” ไม่ยืนยันว่าผิวปกติหรือไม่มีอาการ; ไม่ต้องแสดงคำแนะนำซ้ำ ๆ |
| กลาง | ไม่เข้าเกณฑ์สูง และ (`D ≥ 4` หรือ `T ≥ 4`) | ถ้า dryness เด่น: “อาจสังเกตผิวแห้งหรือตึง” พร้อมแนะนำมอยส์เจอไรเซอร์ตามสภาพผิว; ถ้า thirst เด่น: “ลองจิบน้ำตามความกระหาย” โดยไม่เรียกว่าขาดน้ำ |
| สูง | `D ≥ 7` หรือ (`D ≥ 4` และ `T ≥ 7`) | บอกปัจจัยที่ทำให้ระดับสูง; ถ้าคะแนน dryness สูง อาจแนะนำให้สังเกตผิวแห้ง/ตึงและดูแลอย่างอ่อนโยน หากอาการมาก ต่อเนื่อง หรือกังวล ให้ปรึกษาผู้เชี่ยวชาญ |
| ประเมินไม่ได้ | คะแนนใดคะแนนหนึ่งไม่มีผลทำนาย/อยู่นอกช่วงฝึก | แสดง “ประเมินไม่ได้ในรอบนี้” ห้ามแทนด้วยระดับต่ำ |

กฎและจุดตัดข้างต้นเป็นเพียงข้อเสนอ UX สำหรับทดลอง ต้องทบทวนเมื่อมีผลผิวที่ผู้ใช้รายงานจริง ห้ามนำไปอธิบายว่าเป็นเกณฑ์แพทย์ คะแนนปัจจุบันสร้างจากข้อมูลสังเคราะห์ จึงเป็นสัญญาณทดลอง ไม่ใช่การวัดสุขภาพผิวหรือความน่าจะเป็นของอาการ

การ์ดควรมี `level`, เหตุผลสั้น ๆ เช่น “สัญญาณผิวแห้งจากข้อมูลรอบนี้อยู่ระดับสูง”, ข้อสังเกตที่อาจพบ และคำแนะนำที่สัมพันธ์กับเหตุผลนั้น ไม่ควรนำ thirst กับ dryness มาบวกเป็นคะแนนใหม่โดยไม่มีหลักฐานรองรับ และไม่ควรแสดงอาการที่ไม่ได้สัมพันธ์กับ input ที่มี

แยกสถานะ **ข้อมูลอยู่นอกช่วง/การกระจายที่โมเดลฝึกมา** (`out_of_training_domain`) ออกจาก **ข้อมูลผิดรูปแบบหรือเป็นไปไม่ได้** (`invalid_input`) ให้ชัด: ค่าที่สมเหตุสมผลแต่ไม่เคยอยู่ในช่วงฝึกควรส่งเข้า test mode เพื่อทดสอบ robustness ได้ ส่วนค่าที่ขัดกับข้อจำกัดทางกายภาพหรือ schema ต้องถูกปฏิเสธ ไม่ควรใช้การ clip ค่าให้เข้า train range เพราะจะซ่อนพฤติกรรมจริงของโมเดล

### 2.1 สิวและอาการอื่นที่อาจสนใจ — ยังไม่เปิดเป็นผลทำนายในรุ่นแรก

ผู้ใช้ยกตัวอย่างความเสี่ยงสิวจากการนอนน้อย ดื่มน้ำน้อย และดูแลผิวไม่ดี แต่ input ปัจจุบันยังไม่พอคำนวณระดับสัญญาณสิวอย่างน่าเชื่อถือ จึง **ไม่ควรแสดง “เสี่ยงสิวต่ำ/กลาง/สูง” จาก thirst/dryness เพียงอย่างเดียว** และห้ามใช้ถ้อยคำว่าการดื่มน้ำน้อยทำให้เกิดสิวโดยตรง งานอ้างอิงของ American Academy of Dermatology ระบุว่าการนอนน้อยอาจทำให้สิวที่มีอยู่แย่ลง และผลิตภัณฑ์บางชนิดอาจกระตุ้นการอุดตัน แต่สิวยังเกี่ยวข้องกับหลายปัจจัย จึงไม่ใช่ความสัมพันธ์เหตุ-ผลที่สรุปได้จากข้อมูลรายวันชุดนี้ ([AAD — Acne Causes](https://www.aad.org/public/diseases/acne/causes/acne-causes), [AAD — Adult Acne](https://www.aad.org/public/diseases/acne/really-acne/adult-acne)).

หากต้องการเพิ่มในระยะถัดไป ให้พิจารณา output ชื่อ `next_7_day_breakout_signal` ซึ่งหมายถึง **สัญญาณคาดการณ์การรายงานสิวเห่อ/สิวใหม่ใน 7 วัน** ไม่ใช่การวินิจฉัยสิวหรือความเสี่ยงโรค โดยต้องทำก่อนดังนี้:

- เก็บ label ที่ผู้ใช้รายงานจริง เช่น มีสิวใหม่/สิวเห่อหรือไม่ และระดับที่ผู้ใช้สังเกตได้ในช่วง 7 วัน; ไม่สร้าง label จากกฎเดียวกับ feature
- เก็บบริบทที่จำเป็นและสมัครใจ เช่น ประวัติสิว ความสม่ำเสมอของกิจวัตรดูแลผิว และหมวดผลิตภัณฑ์ดูแลผิว/เครื่องสำอางที่ใช้อยู่; ใช้เวลานอนเป็น feature ได้แต่ไม่ตีความเป็นสาเหตุเดี่ยว ข้อมูลรอบเดือนหรือฮอร์โมนเป็นข้อมูลอ่อนไหว ต้องเป็น optional, ขอ consent ชัดเจน และไม่จำเป็นต่อรุ่นแรก
- ตรวจว่ามีจำนวนข้อมูลและความหลากหลายเพียงพอ ก่อนกำหนด threshold ต่ำ/กลาง/สูงจากการ calibrate และ validation; ห้ามตั้งเปอร์เซ็นต์หรือจุดตัดเป็นข้อเท็จจริงล่วงหน้า
- หากข้อมูลไม่พอ ให้แสดง `insufficient_data` โดยไม่แสดงระดับหรือคำแนะนำเฉพาะสิว
- คำแนะนำที่วางแผนไว้ควรเป็นการดูแลทั่วไปและไม่สั่งยา เช่น ล้างผิวอย่างอ่อนโยน เลือกผลิตภัณฑ์ non-comedogenic หากเหมาะกับผู้ใช้ และหลีกเลี่ยงการบีบ/แกะสิว; หากสิวเจ็บลึก เป็นแผลเป็น หรือเป็นต่อเนื่อง ให้แนะนำพบแพทย์ผิวหนัง ไม่วินิจฉัยหรือระบุยา/ขนาดยา ([AAD — Moisturizer and Acne-Prone Skin](https://www.aad.org/public/diseases/acne/skin-care/moisturizer), [AAD — When to See a Dermatologist](https://www.aad.org/public/diseases/acne/diy/when-derm)).

การดื่มน้ำเป็นข้อมูลบริบท ไม่ใช่ตัวแทนของภาวะผิวหรือภาวะขาดน้ำ และหลักฐานว่าการเพิ่มน้ำดื่มช่วยปรับสภาพผิวโดยตรงยังมีข้อจำกัด ([systematic review](https://pubmed.ncbi.nlm.nih.gov/29392767/), [National Academies — Water](https://nap.nationalacademies.org/read/10925/chapter/2)).

### 2.2 Dashboard ภาพรวมสุขภาวะรายวันและการปรับคำแนะนำตามโปรไฟล์

เพิ่ม dashboard หลังผู้ใช้ส่งข้อมูลและเห็นผลคาดการณ์ โดยใช้ชื่อ **“ภาพรวมสุขภาวะรายวัน”** หรือ **“สัญญาณที่ควรใส่ใจวันนี้”** ไม่ใช้คำว่า “สุขภาพโดยรวมปกติ/ผิดปกติ” หรือสรุปความเสี่ยงโรค เพราะข้อมูลในระบบยังมีเพียงข้อมูลไลฟ์สไตล์และ self-report บางส่วน ไม่ใช่การตรวจสุขภาพ

องค์ประกอบที่เสนอ:

1. **สรุปหนึ่งบรรทัด:** ระดับต่ำ/กลาง/สูงของสัญญาณประจำวันที่ผ่านการนิยามและตรวจสอบแล้ว พร้อมเหตุผล 1–2 ข้อ เช่น “วันนี้ควรใส่ใจเวลานอนและสัญญาณผิวแห้ง”
2. **รายละเอียดสั้น ๆ:** แสดงข้อมูลที่นำมาใช้จริง เช่น เวลานอน, ปริมาณน้ำที่บันทึก, thirst/dryness score และสิ่งที่ผู้ใช้อาจสังเกตได้ โดยแยกค่าที่ผู้ใช้กรอกออกจากค่าที่โมเดลประเมิน
3. **บริบทจากโปรไฟล์:** แสดงคำแนะนำที่เกี่ยวข้องกับข้อมูลที่ผู้ใช้ยินยอมและยังเป็นปัจจุบัน เช่น สถานะการสูบบุหรี่ หรือข้อมูลช่วงที่มีประจำเดือน โดยไม่เปลี่ยนสถานะนั้นให้เป็นคะแนนโรค
4. **คำแนะนำสั้น ๆ:** เลือกเฉพาะ 1–3 ข้อที่เกี่ยวกับสัญญาณและบริบทของผู้ใช้นั้น ไม่แสดงรายการทั่วไปซ้ำ ๆ และไม่ให้คำแนะนำเรื่องยา/ขนาดยา

**การสรุประดับ:** ในรุ่นแรกให้ระดับภาพรวมมาจากสัญญาณประจำวันที่มีนิยามและ validation แล้วเท่านั้น; ช่วงวัยที่เลือกโดยสมัครใจใช้ปรับเกณฑ์คำแนะนำเวลานอนตามวัยเท่านั้น ส่วนโปรไฟล์สูบบุหรี่หรือประจำเดือนใช้ปรับข้อความ/บริบท ไม่บวกเข้า risk score โดยพลการ การรวมหลายสัญญาณต้องไม่เฉลี่ยคะแนนคนละความหมาย หากต้องมีระดับภาพรวม อาจใช้ระดับสูงสุดของสัญญาณรายวันที่ผ่านเกณฑ์ พร้อมแสดงตัวขับระดับอย่างชัดเจน และต้องทดสอบผลกระทบก่อนเปิดใช้ หากไม่มีสัญญาณที่ประเมินได้ ให้แสดง “ประเมินภาพรวมไม่ได้” ไม่ใช่ต่ำ

**ตัวอย่างการใช้บริบท:**

- ผู้ใช้ระบุว่ายังสูบบุหรี่และคืนนี้นอนน้อย: แยกคำแนะนำเรื่องนอนออกจากคำแนะนำสนับสนุนการลด/เลิกบุหรี่ ไม่สรุปว่าเมื่อรวมกับดื่มน้ำน้อยแล้วผู้ใช้อยู่ใน “ความเสี่ยงสุขภาพสูง” โดยไม่มีโมเดลและข้อมูลผลลัพธ์ที่ผ่านการตรวจสอบ การเลิกสูบบุหรี่มีประโยชน์ต่อสุขภาพ แต่ข้อความควรไม่ตำหนิและเสนอทางเลือกขอความช่วยเหลือ ([CDC — Benefits of Quitting Smoking](https://www.cdc.gov/tobacco/about/benefits-of-quitting.html))
- ผู้ใช้บันทึกเองว่ากำลังมีประจำเดือน: แสดงคำแนะนำทั่วไป เช่น พักผ่อน ขยับร่างกายเบา ๆ หรือใช้ความอุ่นบรรเทาปวดเกร็งตามความเหมาะสม; หากมีอาการปวดรุนแรง/แย่ลง เลือดออกมากผิดปกติ หรือกระทบกิจวัตร แนะนำติดต่อบุคลากรทางการแพทย์ ไม่วินิจฉัยสาเหตุหรือสั่งยา ([NHS — Period Pain](https://www.nhs.uk/symptoms/period-pain/), [NHS — Heavy Periods](https://www.nhs.uk/conditions/heavy-periods/), [MedlinePlus — Period Pain](https://medlineplus.gov/periodpain.html))

**ห้ามอนุมานประจำเดือนจากเพศหรือ gender ในโปรไฟล์:** ควรใช้การระบุโดยสมัครใจว่ากำลังมีประจำเดือน/มีอาการหรือไม่ในวันนั้น เพราะเพศกำเนิดหรือเพศสภาพไม่ยืนยันว่าผู้ใช้กำลังมีประจำเดือน และบางคนที่มีประจำเดือนอาจไม่ระบุตัวเองเป็นผู้หญิง ข้อมูลรอบเดือนเป็นข้อมูลอ่อนไหว จึงต้องเป็น optional, ขอ consent แยก, เก็บเท่าที่จำเป็น และมีทางให้แก้ไข/ลบได้

อย่าใช้ข้อความของ dashboard ทำให้ดูเหมือนเป็นแพทย์ (“คุณมีความเสี่ยงสูงต่อโรค…”) ใช้รูปแบบ “ข้อมูลวันนี้ชี้ว่าควรใส่ใจ…”, บอกเหตุผลที่ระบบใช้ และเสนอการดูแลทั่วไปเท่านั้น ส่วนสัญญาณอันตรายที่ผู้ใช้รายงานเองควรแยกเป็นคำแนะนำให้ติดต่อบริการสุขภาพ ไม่รวมกับคะแนนจากโมเดล

| `next_day_low_energy_signal` | คาดการณ์สัญญาณพลังงานต่ำในวันถัดไป เช่น ต่ำ/กลาง/สูง จากประวัติไลฟ์สไตล์ | เช้าวันถัดไปให้ผู้ใช้ประเมินพลังงานตนเอง 0–10 (`0` = ต่ำมาก, `10` = สูงมาก); กำหนดวิธีแปลงเป็นระดับก่อนเริ่มเก็บ | เริ่มจากเวลานอนและความสม่ำเสมอ; พิจารณาเพิ่ม sleep quality หรือกิจกรรมประจำวันแบบสมัครใจ เพราะระยะเวลานอนอย่างเดียวไม่ครอบคลุมความง่วง/อ่อนเพลียทั้งหมด |
| `next_day_thirst_attention` | คาดการณ์ระดับความกระหาย/ความต้องการใส่ใจเรื่องการดื่มน้ำในวันถัดไป ต่ำ/กลาง/สูง | ให้ผู้ใช้รายงานความกระหายหรือปากแห้งในวันถัดไป 0–10; ใช้เป็น label จริง ไม่ใช้ค่า thirst ที่โมเดลทำนาย | แยกจาก thirst score ปัจจุบันซึ่งเป็นการประเมินวันเดียวจากข้อมูลสังเคราะห์; ควรเพิ่มยอดเครื่องดื่มอื่นหรือกิจกรรม/อากาศร้อนเมื่อจำเป็นและยินยอม ห้ามเรียกผลนี้ว่า “ภาวะขาดน้ำ” |

**เหตุผลที่เลือก:** ทั้งสองรายการเชื่อมกับข้อมูลประจำวันที่มี แต่ต้องมี outcome ที่ผู้ใช้รายงานในวันเป้าหมายเพื่อฝึกและตรวจสอบว่าโมเดลพยากรณ์ได้จริง ไม่ควรสร้าง label ด้วยกฎเดียวกับ input แล้วอ้างว่าเป็นความแม่นยำกับสุขภาพจริง

ข้อมูลน้ำที่กรอกในปัจจุบันเป็นน้ำดื่ม ไม่ใช่ total water จากน้ำ เครื่องดื่มอื่น และอาหาร ความต้องการน้ำยังแปรตามสภาพแวดล้อมและกิจกรรม จึงไม่ควรสรุป hydration status จาก `water_intake_ml` เพียงค่าเดียว ([National Academies: Dietary Reference Intakes for Water](https://nap.nationalacademies.org/read/10925/chapter/2)). การวินิจฉัยภาวะขาดน้ำอาจอาศัยอาการ การตรวจร่างกาย และการทดสอบทางห้องปฏิบัติการ จึงไม่ควรใช้ output นี้แทนการวินิจฉัย ([MedlinePlus: Dehydration](https://medlineplus.gov/dehydration.html)).

## 4. ข้อมูลและความยินยอม

ก่อนเริ่มฝึก ให้เพิ่มแบบบันทึกผลจริงรายวันแบบสมัครใจ:

- `reported_energy_level_0_10` — ประเมินพลังงานในเช้าวันถัดไป พร้อมคำอธิบายปลายสเกล
- `reported_thirst_level_0_10` — ประเมินความกระหาย/ปากแห้งในวันถัดไป พร้อมคำอธิบายปลายสเกล
- ผูก label กับวันที่ถูกต้องและข้อมูล input ของวันก่อนหน้า; เก็บเวลาบันทึก แหล่งข้อมูล และเวอร์ชัน consent
- แยก self-report ออกจาก prediction; ห้ามนำผลที่โมเดลทำนายกลับไปเป็น ground truth
- อนุญาตให้ข้าม/แก้ไข/ลบ self-report ตาม consent และนโยบายเก็บข้อมูลสุขภาพของระบบ
- หากยังมีข้อมูลไม่พอ ให้ API ส่งสถานะ `insufficient_history` หรือ `not_available` แทนการสร้างค่าทำนายจำลอง
- โปรไฟล์สำหรับ personalization ใช้ค่าที่ผู้ใช้กรอกเองและแก้ไขได้ เช่น สถานะสูบบุหรี่ `current/former/never/prefer_not_to_say`; ห้ามอนุมานสถานะจากข้อมูลอื่น และห้ามใช้ประวัติสูบบุหรี่เพียงอย่างเดียวสร้างระดับความเสี่ยงเฉียบพลัน
- การให้คำแนะนำประจำเดือนต้องอาศัย check-in โดยสมัครใจ เช่น `currently_menstruating` และอาการที่ผู้ใช้เลือกบันทึก; ไม่อนุมานจากเพศ อายุ หรือข้อมูลประจำเดือนเก่า
- เก็บเฉพาะช่วงวัยที่เลือกโดยสมัครใจ (`13_17`, `18_60`, `61_64`, `65_plus`) ภายใต้ consent สำหรับ age-guidance แยกจาก consent ของสถานะสูบบุหรี่/เช็กอินประจำเดือน; ไม่เก็บวันเกิด และหากไม่เลือกให้ใช้ข้อความทั่วไปที่ไม่อ้างเกณฑ์เฉพาะวัย

สำหรับ sleep guidance ให้ใช้ช่วงวัยที่ผู้ใช้เลือกและยินยอมเท่านั้น: 13–17 ปีโดยทั่วไป 8–10 ชั่วโมง, 18–60 ปีอย่างน้อย 7 ชั่วโมง, 61–64 ปี 7–9 ชั่วโมง, และ 65 ปีขึ้นไป 7–8 ชั่วโมง; กลุ่มเหล่านี้เป็นแนวทางทั่วไปจาก CDC ไม่ใช่การวินิจฉัยหรือการประเมินคุณภาพการนอน หากไม่เลือกช่วงวัยให้ใช้ข้อความทั่วไปโดยไม่ระบุเกณฑ์อายุ ([CDC: About Sleep](https://www.cdc.gov/sleep/about/)).

## 5. แผนโมเดลและการประเมิน

1. **กำหนด target และเวลา:** แยกวัน input กับวัน target ให้ชัด; ใช้ horizon วันถัดไปสำหรับ output ใหม่
2. **เก็บ label จริงก่อน:** ใช้ synthetic data ได้เฉพาะทดสอบ pipeline/UI; ห้ามนับผลจาก synthetic-only evaluation เป็นความแม่นยำสุขภาพจริง
3. **สร้าง baseline:** เริ่มจาก baseline ง่ายและกฎอ้างอิงก่อนทดลองโมเดลที่ซับซ้อน; เปรียบเทียบกับ persistence baseline ที่ทำนายค่าจากวันก่อน
4. **ป้องกัน data leakage:** แบ่ง train/validation/test ตามเวลา และกันผู้ใช้ holdout ไม่ให้ข้อมูลคนเดียวกันรั่วข้ามชุด
5. **สร้างชุดทดสอบนอกช่วงฝึกแยกต่างหาก:** เลือก input ที่สมเหตุสมผลทางกายภาพแต่เลยช่วงหรือการกระจายที่พบใน training; ห้ามนำชุดนี้ไปฝึก จูน Optuna เลือก threshold หรือเลือกโมเดลก่อนสรุปผล เพื่อคงความเป็น holdout
6. **คำนวณความแม่นยำเฉพาะเมื่อมี ground truth:** ถ้าชุดนอกช่วงมีผลจริงที่ผู้ใช้รายงาน/วัดได้ ให้รายงาน metric ของ OOD แยกจาก in-range; ถ้ามีแต่ค่าที่สุ่มหรือ label ที่สร้างจากสูตรเดิม ให้ใช้ทดสอบ input handling/การ abstain เท่านั้น ห้ามรายงานเป็นความแม่นยำสุขภาพจริง
7. **ประเมินตามชนิด target:** ใช้ MAE สำหรับคะแนน 0–10 และ macro-F1/weighted-F1, confusion matrix และ calibration สำหรับระดับต่ำ/กลาง/สูง; แสดงผล in-range และ OOD แยกกัน พร้อมจำนวนตัวอย่าง, class balance, coverage, อัตรา abstain และช่วงความไม่แน่นอน
8. **ไม่ตั้งเป้า accuracy ≥80% โดยไม่มีหลักฐาน:** พิจารณาเปิดใช้เฉพาะเมื่อผลจริงผ่านเกณฑ์ที่กำหนดล่วงหน้า เทียบ baseline ได้ และมีจำนวนข้อมูลเพียงพอ; หากอยู่นอกขอบเขตที่ตรวจสอบแล้ว ให้ abstain หรือแจ้งสถานะ ไม่คาดเดาผล
9. **ทบทวนโดยผู้เชี่ยวชาญ:** ให้ผู้เชี่ยวชาญด้านสุขภาพทบทวนข้อความและขอบเขตก่อนเปิดให้ผู้ใช้ทั่วไป

### UI

- เพิ่ม dashboard “ภาพรวมสุขภาวะรายวัน” หลังผลทำนาย โดยมีระดับสัญญาณ 3 ระดับ/สถานะประเมินไม่ได้, เหตุผลสั้น ๆ, ข้อมูลที่ใช้ และคำแนะนำเฉพาะบุคคลจากโปรไฟล์ที่ยินยอม
- แยก “สัญญาณประจำวัน” ออกจาก “บริบทจากโปรไฟล์” เช่น สถานะสูบบุหรี่หรือ check-in ประจำเดือน; ห้ามทำให้การมีประวัติสูบบุหรี่เพียงอย่างเดียวกลายเป็นระดับสูงของความเสี่ยงรายวัน
- คงการ์ด thirst/dryness เดิม และเพิ่มการ์ดตีความ “ระดับการใส่ใจดูแลผิว” พร้อมเหตุผล
- การ์ดแสดงระดับต่ำ/กลาง/สูงเพียงสามระดับ พร้อมข้อสังเกตที่อาจพบและคำแนะนำสั้น ๆ เฉพาะเมื่อสัมพันธ์กับข้อมูล; ถ้าประเมินไม่ได้ให้แสดงสถานะข้อมูลไม่พอแยกต่างหาก
- ยังไม่แสดงระดับสิวจากข้อมูลน้ำ/การนอนชุดปัจจุบัน; แสดงได้ภายหลังเมื่อมี label และผ่านการประเมินตามแผน
- เพิ่มกลุ่มแยก “แนวโน้มวันถัดไป” สำหรับ low-energy และ thirst attention; แสดงสถานะว่าเก็บข้อมูลไม่พอแทนการแสดงค่าที่ไม่มีหลักฐาน
- ใน `/clients/test` วางแผนให้มีโหมดทดสอบ input ที่อยู่นอกช่วงฝึก โดยแสดงคำเตือน/สถานะ out-of-domain และบันทึกผลจริงแยกจากค่าทำนาย; โหมดผู้ใช้จริงต้องไม่ซ่อนคำเตือนหรือแสดงผลนอกขอบเขตเสมือนเป็น prediction ที่ผ่านการตรวจสอบแล้ว
- คงการไม่แสดง Sleep Score; เวลานอนยังใช้เป็น input ได้
- แสดงเฉพาะคำแนะนำที่สัมพันธ์กับระดับ/เหตุผล ไม่แสดงข้อความซ้ำเมื่อไม่มีสิ่งที่ควรทำ
- ระบุอย่างสั้นว่าผลเป็น wellness signal จากข้อมูลผู้ใช้ ไม่ใช่การวินิจฉัย

## 7. Implementation: ทำแล้วและงานคงเหลือ

### ทำแล้วในรอบนี้

1. เพิ่ม dashboard สามระดับและ rule-based interpretation แยกจากคะแนนโมเดล; ใช้สถานะข้อมูลไม่พอแทนการเดาระดับ
2. เพิ่ม profile context แบบสมัครใจ/consent แยกสำหรับช่วงวัย (ไม่เก็บวันเกิด), สถานะสูบบุหรี่ และ daily menstruation check-in พร้อม endpoint อ่าน/ลบ/ถอน consent
3. เพิ่มการเก็บ self-report outcome แยกจาก prediction เพื่อใช้เป็น ground truth ในอนาคต
4. เพิ่ม API/UI test-only สำหรับ input นอกช่วงฝึก: แสดงค่าดิบจาก estimator พร้อมสถานะ `experimental_out_of_domain`; production endpoint ยังคง abstain และไม่แสดงคำแนะนำจากผล OOD
5. เพิ่ม status ให้ผล next-day energy/thirst เป็น `insufficient_history`; acne ยังคง `insufficient_data` เพราะยังไม่มี label
6. เพิ่ม tests สำหรับ boundary, consent, OOD abstention และ OOD test-only result

### ยังต้องทำก่อนอ้างว่าโมเดลทำนายสุขภาพได้

1. เก็บ pilot user-reported outcomes ที่มี consent และตรวจคุณภาพ/ความครบถ้วน รวมถึงผลสังเกตผิวแห้งที่ตรงกับ target หากจะประเมิน dryness
2. จับคู่ OOD prediction กับ ground-truth จริง; จัด OOD holdout แยกจาก train/validation/tuning และรายงาน metric เฉพาะตัวอย่างที่มี label
3. สร้าง baseline next-day energy/thirst จาก label จริง แล้วทดสอบ chronological + user holdout, calibration และ coverage ก่อนเปิดเป็น prediction
4. ทบทวนข้อความสุขภาพกับผู้เชี่ยวชาญและทดสอบการถอน consent/ลบข้อมูลในสภาพแวดล้อมจริง
5. ยังไม่ฝึกหรือ promote โมเดลใหม่จนมีข้อมูลจริงและ holdout ที่กันไว้ครบ; ห้ามใช้ synthetic labels หรือ prediction เป็น ground truth

## 8. เกณฑ์ผ่านก่อนเปิดใช้

- skin-care attention ไม่ถูกเรียกว่าโรคหรือ clinical risk และไม่ให้ระดับต่ำเมื่อ input score ขาด
- มีเพียงระดับต่ำ/กลาง/สูงสำหรับผลที่ประเมินได้; สถานะข้อมูลไม่พอไม่ถูกแปลงเป็นระดับต่ำ
- ข้อสังเกตและคำแนะนำสั้น ๆ สัมพันธ์กับ input; ไม่มีการสรุปว่าดื่มน้ำน้อยทำให้เกิดสิว หรือคาดการณ์สิวจากคะแนน thirst/dryness อย่างเดียว
- ผลสิว (ถ้าทำภายหลัง) ใช้ label สิวที่ผู้ใช้รายงานจริง มี consent สำหรับข้อมูลอ่อนไหว และผ่าน validation/calibration ก่อนกำหนดระดับ
- dashboard ไม่เรียกผลรวมว่า “ความเสี่ยงสุขภาพโดยรวม”; แสดงเฉพาะสัญญาณรายวันที่รองรับ พร้อมเหตุผลและสถานะข้อมูล
- ช่วงวัยมี consent แยกและใช้เฉพาะเกณฑ์คำแนะนำการนอน; สถานะสูบบุหรี่/ประจำเดือนใช้ปรับคำแนะนำเมื่อผู้ใช้ให้ consent และข้อมูลยังเป็นปัจจุบัน; ไม่อนุมานประจำเดือนจากเพศหรือ gender และไม่บวกบริบทเหล่านี้เข้า risk score โดยไม่มีหลักฐาน/validation
- คำแนะนำเกี่ยวกับบุหรี่และประจำเดือนเป็นข้อมูลทั่วไป ไม่ตำหนิ ไม่วินิจฉัย และมีแนวทางส่งต่อให้ปรึกษาบุคลากรสุขภาพเมื่อผู้ใช้บันทึกอาการรุนแรงหรือผิดปกติ
- ผลพยากรณ์ใหม่ใช้ label จากผู้ใช้จริงที่ตรงกับวันเป้าหมาย; synthetic labels ไม่ถูกนับเป็นผลสุขภาพจริง
- API ระบุ `not_available`/`insufficient_history` เมื่อข้อมูลไม่พอ และ UI ไม่เติมค่าทำนายเอง
- มีการทดสอบค่าที่อยู่นอกช่วงฝึกแต่ยังสมเหตุสมผลใน test-only mode; รายงาน OOD metric แยกจาก in-range เฉพาะตัวอย่างที่มี ground truth จริง
- ค่า input ที่เป็นไปไม่ได้ถูกปฏิเสธเป็น `invalid_input`; input นอกขอบเขตที่รองรับถูกทำเครื่องหมาย `out_of_training_domain`; production abstain ส่วน test-only เปิดเผยค่าทดลองและคำเตือนชัดเจน ไม่ clip input เงียบ ๆ
- OOD holdout ไม่ถูกใช้ฝึก จูน หรือเลือก threshold; synthetic-only OOD test ไม่ถูกอ้างเป็นความแม่นยำสุขภาพจริง
- test split กันทั้งผู้ใช้และเวลา; เปรียบเทียบกับ baseline พร้อม class balance/calibration
- prediction ไม่ถูกนำกลับไปฝึกเป็น label; มี consent, audit trail และวิธีถอน/ลบข้อมูล
- ไม่มี Sleep Score กลับมาใน UI โดยไม่ผ่านการตัดสินใจใหม่

## 9. แหล่งอ้างอิงสำหรับขอบเขตสุขภาพ

- [CDC — About Sleep](https://www.cdc.gov/sleep/about/): แนวทางระยะเวลานอนทั่วไปและอ้างอิงตามวัย
- [National Academies — Dietary Reference Intakes for Water](https://nap.nationalacademies.org/read/10925/chapter/2): total water รวมจากน้ำ เครื่องดื่ม และอาหาร; ความต้องการเปลี่ยนตามบุคคล กิจกรรม และสภาพแวดล้อม
- [MedlinePlus — Dehydration](https://medlineplus.gov/dehydration.html): อาการและแนวทางการวินิจฉัยภาวะขาดน้ำ
- [MedlinePlus — Drowsiness](https://www.medlineplus.gov/ency/article/003208.htm): ความง่วงอาจเกี่ยวกับการนอนไม่พอและมีสาเหตุอื่นได้ จึงไม่ควรสรุปจากชั่วโมงนอนอย่างเดียว
- [CDC — Benefits of Quitting Smoking](https://www.cdc.gov/tobacco/about/benefits-of-quitting.html): ประโยชน์ต่อสุขภาพจากการเลิกสูบบุหรี่และการสนับสนุนการเลิก
- [NHS — Period Pain](https://www.nhs.uk/symptoms/period-pain/): การดูแลทั่วไปและสัญญาณที่ควรปรึกษาบุคลากรสุขภาพเมื่อปวดประจำเดือน
- [NHS — Heavy Periods](https://www.nhs.uk/conditions/heavy-periods/): เมื่อเลือดออกมากหรือกระทบชีวิตประจำวันควรขอคำแนะนำทางการแพทย์
- [MedlinePlus — Period Pain](https://medlineplus.gov/periodpain.html): การดูแลตนเองทั่วไปและกรณีที่ควรติดต่อผู้ให้บริการสุขภาพ
