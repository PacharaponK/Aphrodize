# ความปลอดภัยและการกำกับดูแล

> ตรวจเทียบโค้ดเมื่อ 6 ตุลาคม 2026 ไฟล์นี้กำหนดข้อกำหนดการกำกับดูแล ไม่รับรองว่าตรวจครบทุกข้อ runtime ภาพปัจจุบันรองรับริ้วรอย แต่ไม่ตรวจสิว ถอดพยากรณ์สิวและ UI เก็บข้อมูลแล้ว โดยยังมี API ล้างข้อมูลเดิม รองรับสินค้าระบุชื่อที่ตรวจแล้วภายใต้ gate ความปลอดภัยและข้อมูลซื้อ ดู [ขอบเขตปัจจุบัน](Product%20and%20Scope.md) และ [AI และข้อมูล](../ai/AI%20and%20Data.md)
> ข้อกำหนดด้าน consent, ความเป็นส่วนตัว, ความเป็นธรรม และขอบเขตการกล่าวอ้างของ [ผลิตภัณฑ์และขอบเขต](Product%20and%20Scope.md)

## ขอบเขตผลิตภัณฑ์

Aphrodize เป็น ระบบส่งเสริมสุขภาวะ/การศึกษา สำหรับตรวจและติดตาม ริ้วรอยจากภาพ แล้วใช้ผลลัพธ์ร่วมกับ ข้อกังวลและบริบทที่ผู้ใช้รายงานเพื่อประกอบคำแนะนำผลิตภัณฑ์ ไม่ใช้แทน แพทย์ผิวหนัง หรือการตัดสินใจทางคลินิกของผู้เชี่ยวชาญ

ระบบไม่ทำนายอายุหรือ อายุจากลักษณะภายนอก จากใบหน้า เพราะศัลยกรรม หัตถการ พันธุกรรม และปัจจัยแวดล้อมทำให้ลักษณะใบหน้าไม่จำเป็นต้องสอดคล้องกับอายุจริง อีกทั้งผลลัพธ์ดังกล่าวอาจก่อให้เกิดการตีความและผลกระทบทางจิตใจที่ไม่จำเป็น

ระบบไม่ทำ การจดจำใบหน้าเพื่อระบุตัวตน ไม่สร้าง เวกเตอร์ชีวมิติสำหรับระบุตัวตน ไม่ยืนยันชนิดหรือสาเหตุของสิวและริ้วรอย และไม่ประเมินประสิทธิผลของผลิตภัณฑ์หรือหัตถการ แบบสอบถามใช้เพื่อแสดงปัจจัยที่อาจเกี่ยวข้องตามข้อมูลที่ผู้ใช้รายงานเท่านั้น

## ถ้อยคำที่ต้องใช้

- ใช้ **ตรวจพบจากภาพ** ไม่ใช้ถ้อยคำวินิจฉัย
- ข้อมูลสิวเดิมเป็น **ผู้ใช้รายงาน** ไม่อ้างว่าตรวจพบจากภาพ เพราะ runtime ไม่มี acne detector
- ใช้ **คะแนนริ้วรอย** และอธิบายว่าเป็นค่าจากโมเดล ไม่ใช่คะแนนสุขภาพหรือความงาม
- แยก **ผู้ใช้รายงาน** ออกจากผลที่โมเดลตรวจพบ และแสดง source ของ signal
- ใช้ **แนวโน้ม** เฉพาะการเปรียบเทียบภาพที่ผ่าน แนวทางถ่ายภาพ และ เกณฑ์คุณภาพ
- ใช้ **ปัจจัยที่อาจเกี่ยวข้องตามข้อมูลที่ผู้ใช้รายงาน** ไม่ใช้ถ้อยคำยืนยันสาเหตุ
- แสดง confidence, image-quality limitation และ รุ่นโมเดล ใกล้ผลลัพธ์
- ไม่แสดงอายุที่คาดการณ์ สาเหตุ คำแนะนำการรักษา หรือการรับรองผล
- ไม่แสดง การวินิจฉัย, คำกล่าวอ้างเกี่ยวกับโรค หรือ คำกล่าวอ้างการรักษา

## Consent and ความเป็นส่วนตัว

ภาพใบหน้าเป็นข้อมูลอ่อนไหว ระบบต้องใช้ การใช้ข้อมูลเท่าที่จำเป็น ตั้งแต่เริ่ม:

- ขอ ความยินยอมหลังรับทราบข้อมูล ก่อน upload
- บอกวัตถุประสงค์และระยะเวลาการเก็บ
- ให้ถอน consent และลบภาพได้
- จำกัดสิทธิ์การอ่าน object ใน MinIO
- ใช้ รหัสแทนตัวตน แทนชื่อจริง
- ไม่บันทึก เวกเตอร์ใบหน้า สำหรับระบุตัวตน
- ไม่บันทึกภาพ token คำตอบแบบสอบถาม หรือข้อมูลอ่อนไหวลง log
- ไม่ใช้ภาพผู้ใช้ทำ training หรือ retraining โดยอัตโนมัติ

การลบต้องครอบคลุม ภาพต้นฉบับ ภาพที่ปรับมาตรฐาน และ mask และผลวิเคราะห์ที่เชื่อมกับภาพนั้น

## ความเป็นธรรม

วัด error แยกตาม สีผิว, สัดส่วนตัวแทนเพศ/อัตลักษณ์ทางเพศ, บริเวณใบหน้า และ image quality เท่าที่ label อนุญาต รายงาน ขนาดตัวอย่าง และ limitation เมื่อข้อมูลบางกลุ่มน้อย ไม่สรุปว่าระบบ fair จาก aggregate metric เพียงค่าเดียว

Dataset split ต้องป้องกัน การรั่วไหลของตัวตนข้ามชุดข้อมูล ตาม [AI และข้อมูล](../ai/AI%20and%20Data.md) และรายงานผลแยกตาม subgroup ตามข้อมูลที่มี Image/UV tracking ใช้ MLflow ตาม flow ของแต่ละระบบ; Daily Health ส่งเฉพาะ aggregate metrics/cohort counts ไม่ส่งรายบุคคลหรือสำเนา health model artifacts ดู [เส้นทางองค์ประกอบระบบ](../architecture/Component-Flows.md)

## ความปลอดภัยของคำแนะนำ

- แนะนำ หมวดผลิตภัณฑ์, สารออกฤทธิ์ หรือสินค้าที่ตรวจทานแล้วและมี source/rationale ตาม safety gates
- ตรวจ การแพ้, การระคายเคือง, ความไวต่อการระคายเคือง, routine เดิม และ ข้อห้ามใช้ ก่อนแสดงทุกครั้ง
- Recommendation ที่อ้างผลภาพต้องไม่แสดงเมื่อ image quality/confidence ต่ำ
- Recommendation จาก concern ที่ผู้ใช้รายงานต้องระบุว่าไม่ได้เป็นผลตรวจจากภาพ
- ไม่แสดง recommendation เมื่อผู้ใช้รายงานอาการรุนแรง มี ข้อห้ามใช้ หรือข้อมูลไม่พอสำหรับกฎนั้น
- ไม่แนะนำ prescription หรือการรักษาเฉพาะโรค

## ทะเบียนความเสี่ยง

| ความเสี่ยง | ผลกระทบ | วิธีลด |
|---|---|---|
| แสง กล้อง มุม หรือสีหน้าเปลี่ยน | คะแนนเปลี่ยนทั้งที่ผิวไม่เปลี่ยน | แนวทางถ่ายภาพ + เกณฑ์คุณภาพ |
| ความเอนเอียงของชุดข้อมูล | error สูงในบาง subgroup | การประเมินกลุ่มย่อย และรายงาน limitation |
| สับสนระหว่างผลภาพกับข้อมูลที่ผู้ใช้รายงาน | ผู้ใช้เชื่อว่า AI ตรวจพบสิ่งที่ไม่ได้รองรับ | เก็บและแสดง source เป็น `image` หรือ `self_reported` |
| ลักษณะคล้ายสิวถูกตีความเป็นการวินิจฉัย | ผู้ใช้รักษาตนเองผิด | ใช้ถ้อยคำไม่วินิจฉัย แสดง confidence และส่งต่อเมื่อรายงานอาการรุนแรง |
| ตีความ คะแนนเป็นสุขภาพหรือความงาม | ผลกระทบทางจิตใจ | ใช้ถ้อยคำเป็นกลางและอธิบายขอบเขต |
| ตีความ ปัจจัยที่อาจเกี่ยวข้อง เป็นสาเหตุ | ข้อมูลสุขภาพที่ทำให้เข้าใจผิด | แสดงที่มาจากแบบสอบถาม ใช้ถ้อยคำว่าอาจเกี่ยวข้อง และเก็บ รุ่นกฎ |
| ผลโมเดลถูกตีความเป็น การวินิจฉัย | รักษาล่าช้าหรือรักษาผิด | ใช้ถ้อยคำเป็นกลาง ไม่แสดง คำกล่าวอ้างเกี่ยวกับโรค และแนะนำพบ แพทย์ผิวหนัง เมื่อผู้ใช้รายงานอาการรุนแรง |
| Recommendation ไม่เหมาะกับผู้ใช้ | ระคายเคืองหรืออันตราย | ข้อห้ามใช้ check, safety rules และ low-confidence block |
| ศัลยกรรมหรือหัตถการเปลี่ยนลักษณะใบหน้า | trend เปลี่ยนโดยไม่สะท้อน การเปลี่ยนตามวัยตามธรรมชาติ | ไม่ทำนายอายุ ไม่สรุปสาเหตุ และให้ผู้ใช้ตีความร่วมกับบริบทของตนเอง |
| ภาพใบหน้ารั่ว | ความเป็นส่วนตัว harm สูง | consent, access control, retention และ deletion |
| ข้อมูลติดตามน้อย | trend ไม่มีความหมาย | แสดง ข้อมูลสังเกตดิบ และไม่ forecast |

## การตรวจการกำกับดูแล ก่อนเผยแพร่

- Dataset และ model license รองรับรูปแบบการเผยแพร่
- Consent version และ retention period ถูกกำหนดแล้ว
- มีเกณฑ์ image quality ที่ตรวจสอบได้
- Rule table ผ่าน unsafe-output tests และตรวจสอบย้อนกลับด้วย รุ่นกฎ ได้
- ทุก recommendation ตรวจสอบย้อนกลับได้ว่าใช้ image signal, self-reported signal และ knowledge source ใด
- เอกสารโมเดล ระบุ dataset, metrics, subgroup limitations และ วัตถุประสงค์การใช้
- UI/API ไม่มี age prediction, การวินิจฉัย หรือ คำกล่าวอ้างการรักษา
- ผลตอบกลับ API และ log ไม่มี secret หรือข้อมูลส่วนบุคคลเกินจำเป็น
- ผู้ใช้ลบภาพและ derived artifacts ได้จริง
