## ข้อค้นพบ

เว็บจริงมีผลิตภัณฑ์ 29 รายการ และ 8 รายการระบุ `eye_contour` จึงไม่ใช่ปัญหาว่าฐานข้อมูลไม่มีผลิตภัณฑ์รอบดวงตา อย่างไรก็ตาม เส้นทางวิเคราะห์ภาพปัจจุบันปิดการใช้ผลภาพเพื่อเลือกผลิตภัณฑ์ด้วยเหตุผล `landmark_roi_not_calibrated` แม้ความเชื่อมั่นของโมเดลผ่านนโยบาย manual review แล้ว

ทดสอบผ่าน https://aphrodize.duckdns.org/api/analysis ด้วยเซสชันทดสอบใหม่ ไม่ใช้บัญชีหรือภาพของผู้ใช้คนอื่น ให้ความยินยอมเฉพาะการวิเคราะห์ ไม่ให้ความยินยอม annotation หรือ training บันทึกเฉพาะผลสรุป ไม่มี cookies, tokens, ภาพใบหน้า หรือ URL ของภาพผลในรายงาน

API container revision: `7e3b6c2d5fdb900358690f0d3d460ae9cd823323` ซึ่งต่างจาก HEAD ของ workspace จึงทดสอบกฎเลือกสินค้าด้วยโค้ดใน container ที่ทำงานจริงและอ่านแคตตาล็อกจริง ไม่ใช้แคตตาล็อกในไฟล์เป็นตัวแทนฐานข้อมูล

## การทดสอบกฎคำแนะนำ 32 กรณี

รัน `recommendations_for` และ `attach_catalog_products` ใน API container กับฐานข้อมูลสินค้าจริง ใช้ข้อมูลโปรไฟล์จำลอง จึงไม่เขียนหรือแก้ไขข้อมูลผู้ใช้ รวม 26 กรณีผลวิเคราะห์จำลอง, 4 กรณีใช้ผลภาพจริง, และ 2 กรณีตรวจสาเหตุแบบ counterfactual ทุก assertion ผ่าน

- ผิวแห้ง/ปกติ/ผสม/มัน × ความไวต่ำ/ปานกลาง: 8 กรณี ผลภาพจำลองที่ eligible และมีพื้นที่รอบดวงตา 5% เลือกสินค้ารอบดวงตาได้ทั้งหมด และทุกสินค้าระบุ eye_contour
- พื้นที่รอบดวงตา 0%, 1%, 1.65%, 1.81%: ไม่มีหมวดเฉพาะรอบดวงตา; 1.82%, 2%, 3.35%, 10%: มีหมวดเฉพาะรอบดวงตา (เกณฑ์ในโค้ดจริงคือ ratio >= 0.0165 × 1.1 = 1.815%; 182/10000 เป็นค่าทดสอบจำนวนพิกเซลแรกที่ผ่าน)
- พบเฉพาะหน้าผาก: หมวดสำหรับใบหน้า ไม่มีหมวดรอบดวงตา
- รอบดวงตา 10% + หน้าผาก 5%: หมวดรอบดวงตาขึ้นก่อนใบหน้า
- gate ไม่ผ่าน, คุณภาพ 0.79, อายุต่ำกว่า 18, ไม่ระบุอายุ: ไม่แนะนำหมวดรอบดวงตา
- ผิวไวสูงหรือรายงานแพ้: safety_blocked
- งบ 500 บาท: มีหมวดรอบดวงตา แต่ไม่มีสินค้าที่ตรงงบ; งบ 1,000 บาท: พบ Curél Eye Cream และ Vichy Mineral 89 Eyes Serum
- ผลภาพจริงทั้งสองที่ completed: ใช้เฉพาะโปรไฟล์ ไม่มีหมวด R-WRINKLE-EYE-001 หรือ R-WRINKLE-FACE-001

Counterfactual สองกรณีเปลี่ยนข้อมูลในหน่วยความจำเท่านั้น: ย้าย experimental_score ไป derived_score และตั้ง gate eligible=true โดยคงพื้นที่พิกเซลและความเชื่อมั่นเดิม ไม่แก้ policy, database หรือผลภาพที่บันทึกจริง:
- ภาพสาธิต Aphrodize: ได้ Curél Intensive Moisture Care Moisture Repair Eye Cream, Paula’s Choice Pro-Collagen Peptide Firming Eye Serum และ C5 Super Boost Eye Cream สำหรับโปรไฟล์ผิวแห้ง อายุ 25–34 ความไวต่ำ
- Grace Hopper: ได้หมวดสำหรับใบหน้า พร้อมสินค้าในแคตตาล็อก

จึงแยกสาเหตุได้ว่าแคตตาล็อกและกฎจับคู่สินค้าใช้งานได้เมื่อรับผลภาพที่ eligible แต่ผลจาก pipeline ปัจจุบันถูกปิดก่อนถึงกฎนี้

## จุดที่ทำให้ปิดการใช้ผลภาพ

`backend/wrinkle/service.py:201–205` ตั้ง gate_passed=false เมื่อ regional_rois ไม่ใช่ None เพราะนโยบาย release เดิมรับรอง fixed ROIs แต่ยังไม่ครอบคลุม landmark ROIs ใหม่ `analyze_bytes` ส่ง regional_rois เป็น dict เสมอ (เริ่มต้น {} และใส่ผลเมื่อ detect สำเร็จ) จึงเข้าเงื่อนไขนี้ในเส้นทางปัจจุบัน

`backend/services/analysis_service.py` ยอมใช้เฉพาะ derived_score ที่ผ่าน gate; experimental_score จึงไม่ถูกนำมาเพิ่มหมวดริ้วรอย

พบอีกข้อจำกัด: endpoint คำแนะนำในเว็บที่ deployed ตอบ HTTP 401 สำหรับเซสชันวิเคราะห์แบบไม่เข้าสู่ระบบ จึงไม่ได้ทดสอบหน้าผลิตภัณฑ์ด้วยบัญชีจริง การทดสอบเลือกสินค้าด้านบนเรียกฟังก์ชันใน container จริงโดยตรง ไม่ใช่การทดสอบ UI หลังเข้าสู่ระบบ

## แนวทางแก้ที่ต้องทำต่อ

1. กำหนดและทบทวนนโยบาย release ให้ครอบคลุม landmark ROI รุ่นที่ใช้อยู่ พร้อมหลักฐานและ regression tests ก่อนเปิดให้ผลภาพเลือกสินค้า ไม่ควรปลด gate โดยไม่มีนโยบายรองรับ
2. แสดงเหตุผลเฉพาะเมื่อผลภาพใช้เลือกสินค้าไม่ได้ แทนข้อความความเชื่อมั่นกว้าง ๆ
3. แสดงเหตุผลเมื่อมีหมวดที่ตรงบริเวณ แต่ไม่มีสินค้าเพราะงบหรือเงื่อนไขอื่น
4. หลังแก้ ทดสอบภาพจริงกับบัญชีทดสอบที่มีโปรไฟล์ และตรวจคำตอบ API พร้อมหน้าผลิตภัณฑ์อีกครั้ง

งานนี้เป็นการตรวจสอบและทดสอบ ไม่ได้เปลี่ยนเกณฑ์ inference, deployment หรือข้อมูลแคตตาล็อก ระบบเลือกสินค้าตามฉลากและข้อมูลที่กรอก; การทดสอบนี้ไม่รับรองผลลัพธ์การใช้ผลิตภัณฑ์หรือความเหมาะสมทางการแพทย์
