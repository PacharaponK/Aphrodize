# แผนพัฒนา UV และคำแนะนำกันแดด: งานที่เหลือ

**ผลการดำเนินการ 29 กันยายน 2026:** ระยะ 4 ตรวจฐาน WOUDC แล้วไม่พบ UV ที่วัดจริงครบสามพื้นที่ (พบเฉพาะโอโซน 597 ระเบียน) จึงยังไม่ผ่านเงื่อนไขของระยะ 5 และไม่ฝึกตัวปรับเมฆ ระยะ 6–8 ใช้งานต้นแบบ clear-sky ได้แล้ว; ระยะ 9 ผ่านการทดสอบ API ทั้งสามเมือง, build หน้าเว็บ และทดสอบหน่วย แต่การตรวจด้วยเบราว์เซอร์อัตโนมัติทำไม่ได้เพราะตัวช่วย Windows เริ่มไม่สำเร็จ ระยะ 10 มีงานรีเฟรชทุก 6 ชั่วโมง, เช็กข้อมูลเก่า, log และขั้นตอน retrain/rollback รายละเอียดอยู่ใน [รายงานส่งมอบ](uv-implementation.md)

สถานะ ณ 29 กันยายน 2026: ระยะ 1–3 เสร็จแล้ว มีข้อมูล TEMIS สามเมือง, SARIMAX ที่ฝึกเอง, การทดสอบย้อนหลัง และ [notebook ประเมินผล](../models/time-series/uv/uv_model_evaluation.ipynb) โมเดลทำนาย **UV แบบท้องฟ้าโปร่ง ณ เที่ยงสุริยะ**; ยังไม่ได้พิสูจน์ว่าแม่นยำต่อ UV จริงในวันที่มีเมฆ [TEMIS อธิบายชนิดข้อมูล](https://temis.nl/uvradiation/UVarchive/stations_uv.php)

## หลักการตลอดโครงการ

- ดาวน์โหลดข้อมูลดิบผ่าน API ได้ แต่ฝึกและให้บริการโมเดลของโครงการเอง ห้ามใช้ API ที่คืนค่าพยากรณ์ UV สำเร็จรูปแทนโมเดล
- รองรับกรุงเทพ สงขลา และเชียงใหม่ ผู้ใช้เลือกพื้นที่เอง ไม่อ้างว่าพยากรณ์ได้ละเอียดถึงพิกัดทุกจุดในจังหวัด
- แสดงวันที่ข้อมูลล่าสุด วันที่พยากรณ์ ระยะล่วงหน้า แหล่งข้อมูล และคำว่า **ท้องฟ้าโปร่ง** ทุกครั้งที่แสดงค่า TEMIS/SARIMAX
- แยกการประเมินความแม่นยำของโมเดลออกจากการตรวจความปลอดภัยของคำแนะนำกันแดด

## จุดตัดสินใจสำคัญ

**ถ้าพบ UV all-sky ที่เหมาะกับทั้งสามเมือง:** ทำระยะ 5 แล้วใช้ข้อมูลเมฆย้อนหลังที่เป็น *forecast ณ เวลานั้น* เพื่อกันข้อมูลรั่วไปยังอดีต [Open-Meteo มีเอกสาร historical/previous forecast runs](https://open-meteo.com/en/docs/historical-forecast-api) ห้ามใช้ค่า UV พยากรณ์สำเร็จรูปจากบริการอื่นเป็นคำตอบของโมเดลโครงการ ช่วงปี 2025–2026 ถูกใช้ตรวจ SARIMAX ไปแล้ว; การปรับโมเดลใหม่ต้องกันช่วงทดสอบที่ยังไม่ถูกใช้เลือกแนวทาง หรือใช้ rolling-origin protocol ที่ล็อกไว้ก่อนทดลอง

**ถ้าไม่พบข้อมูล all-sky ที่เพียงพอ:** ข้ามระยะ 5 ทำต้นแบบด้วย SARIMAX clear-sky เดิมและแสดงข้อมูลเมฆเป็นบริบทเท่านั้น ไม่คำนวณตัวเลข UV หลังปรับเมฆ และไม่กล่าวว่าคำแนะนำผลิตภัณฑ์ผ่านการตรวจเทียบ UV จริง [WHO ระบุว่าเมฆบางชนิดอาจยังทำให้ UV สูง](https://www.who.int/news-room/questions-and-answers/item/radiation-ultraviolet-%28uv%29)

## งานที่โค้ดปัจจุบันต้องเปลี่ยน

- `backend/api/schemas/product.py` รองรับหมวด `sunscreen` แต่ยังไม่มีช่อง SPF/UVA/ความทนน้ำที่ตรวจสอบได้ ต้องเพิ่มพร้อม validation และปรับหน้าจัดการสินค้า
- `frontend/src/app/recommendation/page.tsx` ยังเป็นข้อความตัวอย่าง ต้องเชื่อม API จริงและแสดงที่มาของคำแนะนำ
- `backend/services/analysis_service.py` ผูกคำแนะนำทั่วไปกับผลภาพ; คำแนะนำ UV ต้องมีบริการแยกเพื่อให้เลือกเมืองได้โดยไม่ต้องผ่านการวิเคราะห์ภาพ
- ระบบมี FastAPI, ARQ worker และโครงสร้างบันทึกเวอร์ชันโมเดลอยู่แล้ว ควรใช้ส่วนที่มีอยู่ก่อนเพิ่มระบบใหม่

กฎสุขภาพจะอิงแนวทางที่ตรวจทานแล้ว เช่น [WHO แนะนำกันแดด broad-spectrum SPF 30+ และการทาซ้ำระหว่างอยู่กลางแจ้ง](https://www.who.int/news-room/questions-and-answers/item/radiation-protecting-against-skin-cancer) แต่ตัวเลข UV จากโมเดลเพียงอย่างเดียวไม่ควรใช้ยืนยันว่าผลิตภัณฑ์ใดเหมาะกับสภาพผิวหรือกิจกรรมของผู้ใช้

**ลำดับเริ่มงาน:** ระยะ 4 ก่อน แล้วตัดสินว่าจะทำระยะ 5 หรือใช้เส้นทาง clear-sky จากนั้นจึงทำ 6 → 7 → 8 → 9 → 10 ระยะ 4 เป็นความเสี่ยงหลักของกำหนดเวลา เพราะความพร้อมของข้อมูล UV จริงยังไม่ยืนยัน
