# แผนหน้าแผนที่ UV ประเทศไทย

วันที่วางแผน: 1 ตุลาคม 2026 (Asia/Bangkok)

**สถานะ:** พัฒนาและตรวจแล้วตามขอบเขตที่ผู้ใช้อนุมัติ ดู [คู่มือใช้งานและผลตรวจ](uv-thailand-map.md) ข้อจำกัดการเรียก API สดที่บันทึกไว้ระหว่างวางแผนได้รับการแก้ไขแล้ว และตรวจครบอีก 74 จังหวัดได้จริง

**ข้อกำหนดล่าสุดแทนแผนผสมด้านล่าง:** ผู้ใช้ให้แยกตัวเลือกแหล่งข้อมูลแล้ว โหมด API ใช้ Open-Meteo ครบ 77 พื้นที่ โหมดโมเดลใช้เฉพาะสามจังหวัด ไม่มีการระบายสีจากสองแหล่งร่วมกัน ดูคู่มือปัจจุบันด้านบน

## ขอบเขตและข้อสรุป

เพิ่มหน้า `/uv-map` แสดงประเทศไทย 77 พื้นที่ ได้แก่ 76 จังหวัดและกรุงเทพมหานคร เลือกวันนี้/พรุ่งนี้ คลิกจังหวัดเพื่อดูค่า UV ระดับความเสี่ยง แหล่งข้อมูล พิกัดตัวแทน และเวลาอัปเดต

- กรุงเทพฯ สงขลา และเชียงใหม่: ใช้เส้นทางโมเดล SARIMAX ของโครงการที่มีอยู่แล้ว
- อีก 74 จังหวัด: ใช้ Open-Meteo ตามพิกัดตัวแทนจังหวัด ไม่ขยายโมเดลสามเมืองไปทำนายพื้นที่ที่ไม่ได้ประเมิน
- ค่าแต่ละจังหวัดเป็นค่าที่จุดตัวแทน ไม่ใช่ค่าเฉลี่ยหรือค่าที่วัดครอบคลุมทั้งจังหวัด ต้องระบุข้อจำกัดนี้ใกล้แผนที่
- เริ่มด้วย clear-sky ทั้งสองแหล่ง ไม่ใช้ค่า API เป็นเป้าหมายฝึกหรือเป็นหลักฐานยืนยันความแม่นยำของโมเดลเรา

คำขอใหม่นี้ขยายข้อกำหนดใน `uv-remaining-development-plan.md` ที่เคยห้ามใช้ API พยากรณ์ UV สำเร็จรูป: อนุญาตเฉพาะจังหวัดนอกสามพื้นที่โมเดลเดิม ต้องปรับเอกสารเดิมให้สอดคล้องเมื่อเริ่มพัฒนา

## หลักฐานจากระบบปัจจุบัน

- `scripts/refresh_uv_forecast.py` โหลดโมเดลสามเมืองและเขียน snapshot แบบ atomic มี weather จาก Open-Meteo อยู่แล้ว
- `backend/services/uv_service.py` อ่าน snapshot และมี `uv_level()` ที่ใช้ร่วมกันได้ ตรวจอายุ snapshot ไม่เกิน 8 ชั่วโมงและช่วงวันนี้/พรุ่งนี้
- `/api/v1/uv/recommendation` รองรับสามเมือง; Next.js proxy เก็บ Basic credentials ฝั่ง server
- Frontend ใช้ Next.js/React และยังไม่มี dependency สำหรับ GIS หรือแผนที่
- โมเดลเดิมทำนาย clear-sky ณ เที่ยงสุริยะ ไม่ใช่ UV ปัจจุบันหรือ UV ที่วัดจริงหลังผลของเมฆ
- `build_snapshot()` ปัจจุบันอาจคืนค่า TEMIS ของวันที่มีข้อมูลแล้วแทน forecast ต้องรักษา `value_kind` ให้ตรงความจริง หากกำหนดว่าทั้งสามพื้นที่ต้องแสดง prediction เสมอ ต้องปรับเส้นทางนี้และตรวจการใช้ข้อมูล ณ forecast origin โดยไม่ขยาย horizon เกินสองวันที่ประเมินไว้

## API และความหมายของค่า

[Open-Meteo Forecast API](https://open-meteo.com/en/docs) รองรับหลายพิกัดใน request เดียวและมี `uv_index_clear_sky_max` เป็นค่าสูงสุดรายวันภายใต้ท้องฟ้าโปร่ง

พารามิเตอร์เริ่มต้น: `latitude`, `longitude`, `daily=uv_index_clear_sky_max`, `forecast_days=2`, `timezone=Asia/Bangkok` แบ่งพิกัดเป็น batch ขนาดพอเหมาะหาก URL ยาวหรือผู้ให้บริการจำกัดจำนวนจุด ตรวจ quota ตามจำนวน location ไม่สมมติว่า batch ทั้งหมดนับเป็นหนึ่ง API call

**ความต่างที่ต้องแสดง:** ค่าโมเดล ณ เที่ยงสุริยะกับ daily maximum ของ API ยังเป็นคนละ aggregation แม้ทั้งคู่ clear-sky จึงใช้เป็นภาพรวมความเสี่ยงช่วงกลางวันและระบุชนิดค่าของแต่ละแหล่ง ไม่อ้างว่าเทียบกันแบบตรงตัวหรือใช้จัดอันดับความแม่นยำ หากต้องการตัวเลขที่เวลาเดียวกันจริง ต้องตรวจ hourly `uv_index_clear_sky` และวิธีจับคู่เที่ยงสุริยะก่อนทำรุ่นถัดไป ไม่แทนเที่ยงสุริยะด้วย 12:00 น. โดยไม่อธิบาย

[เงื่อนไขบริการ](https://open-meteo.com/en/terms): Free API สำหรับ non-commercial และข้อมูลภายใต้ CC BY 4.0 ต้องให้ attribution; จำกัดต่ำกว่า 10,000 calls/day, 5,000/hour และ 600/minute การเปิดใช้งานเชิงพาณิชย์ต้องเลือกสิทธิ์บริการที่เหมาะสม ดู [pricing](https://open-meteo.com/en/pricing)

ตรวจเอกสารได้แล้ว แต่การเรียก API สดจากเครื่องนี้ถูกปฏิเสธการเชื่อมต่อ และเครื่องมือเว็บเปิด URL ทดสอบไม่ได้ จึงยังไม่ยืนยัน response หรือความครบถ้วนทุกจังหวัดจากการทดสอบจริง

## ข้อมูลจังหวัดและแผนที่

สร้าง registry คงที่ 77 รายการ: `province_id`, ชื่อไทย, latitude/longitude ของจุดตัวแทน, และ `model_city` สำหรับสามพื้นที่ ใช้รหัสจังหวัดที่คงที่เชื่อมข้อมูลกับ shape ห้าม join ด้วยชื่อไทย/อังกฤษอย่างเดียว ตรวจ alias และจังหวัดบึงกาฬโดยเฉพาะ

[geoBoundaries THA ADM1 metadata](https://www.geoboundaries.org/api/current/gbOpen/THA/ADM1/) ระบุ `admUnitCount=77` และมี simplified GeoJSON แต่ขอบเขตแทนปี 2017 ต้องตรวจความเหมาะสมและครบ 77 ID ก่อนใช้ ชุดนี้ระบุ ODbL 1.0 จึงต้องรักษา license/attribution และตรวจข้อกำหนดต่อข้อมูลที่ดัดแปลง ไม่สมมติว่าเป็น CC BY ตามชื่อ gbOpen

แปลง geometry ที่ตรวจแล้วเป็น SVG asset ครั้งเดียว เก็บในโปรเจกต์พร้อมข้อมูลที่มาและ license ใช้ SVG `viewBox` ให้ปรับตามจอ ไม่ต้องโหลดแผนที่จากภายนอกตอนเปิดหน้า รุ่นแรกไม่มีแผนที่ถนนหรือ tile server

## การไหลของข้อมูล

`งาน refresh ทุก 6 ชั่วโมง → ผลสามเมือง + Open-Meteo 74 จังหวัด → map snapshot → FastAPI → Next.js proxy → SVG map`

1. ต่อยอดงาน refresh เดิม ไม่เพิ่ม service/queue ใหม่สำหรับงานนี้
2. แยกความล้มเหลวแต่ละแหล่ง: TEMIS/โมเดลล่มต้องไม่หยุดการ refresh อีก 74 จังหวัด; API ล่มต้องไม่ทำให้ผลโมเดลที่สดหาย
3. เขียน `storage/artifacts/uv/map_snapshot.json` แยกจาก snapshot เดิมเพื่อลดผลกระทบต่อหน้า recommendation เก็บ snapshot รวมแบบ atomic
4. แต่ละจังหวัดมี `source`, `value_kind`, `aggregation`, `representative_point`, `generated_at`, `model_version` ถ้ามี, `status` และค่าแยกวันที่
5. คำนวณระดับด้วย `uv_level()` เดิม ตรวจค่าต้องเป็นเลข finite ไม่ติดลบ ตรวจวันที่ Asia/Bangkok รายการพิกัด และ response ก่อนเผยแพร่
6. เก็บค่าล่าสุดที่ยังอยู่ในเกณฑ์ความสดได้; เมื่อเกิน 8 ชั่วโมงหรือวันที่ไม่ตรง ให้คืนสถานะ stale พร้อม `uv_index=null` และสีเทา ไม่แทนด้วย 0 ไม่ใช้ API แทนสามเมืองโดยอัตโนมัติ
7. เพิ่ม `GET /api/v1/uv/map?day=today|tomorrow` และ `/api/uv/map` proxy ใช้การป้องกัน credentials แบบเดิม โหลดทั้งประเทศครั้งเดียวต่อการเปิด/refresh หน้า ไม่ยิง API ภายนอกต่อจังหวัดจาก browser
8. แหล่งเดียวล่มให้ตอบข้อมูลบางส่วนพร้อมสถานะรายจังหวัด; ถ้าไม่มีข้อมูลที่ใช้ได้เลย แสดงสถานะ unavailable อย่างชัดเจน

## หน้าใช้งานรุ่นแรก

- หัวข้อ “แผนที่ UV ประเทศไทย — ท้องฟ้าโปร่ง” พร้อมวันที่ วันนี้/พรุ่งนี้ และเวลาอัปเดต
- ระบายสีระดับ UV จากกฎเดิม; legend มีทั้งสี ชื่อระดับ และช่วงตัวเลข ใช้สีเทาสำหรับไม่มีข้อมูล
- แสดงป้ายหรือสัญลักษณ์แยกสามจังหวัดที่ใช้โมเดลเรา ให้ข้อมูล source อยู่ในรายละเอียดทุกจังหวัด
- Hover/focus แสดงชื่อและค่า; click/keyboard เปิดรายละเอียดจังหวัด บนมือถือใช้แตะและแสดงรายละเอียดใต้แผนที่
- มีช่องเลือกจังหวัดหรือตารางค่าเป็นทางเข้าถึงสำรอง เพื่อให้ผู้ใช้ keyboard/screen reader ไม่ต้องอาศัย shape และสี
- รายละเอียดแสดงค่า UV ชนิดค่า แหล่งข้อมูล จุดตัวแทน เวลาอัปเดต สถานะ และคำแนะนำจากกฎเดิม หากไม่มีค่าจะไม่แสดงคำแนะนำที่คำนวณจาก UV สมมติ
- ลิงก์หน้าใหม่จากส่วน UV บน dashboard ใช้ component/style เดิมตาม `frontend/DESIGN.md`

## ลำดับลงมือและเกณฑ์ผ่าน

| ระยะ | งาน | เกณฑ์ผ่าน |
| --- | --- | --- |
| 1 | ตรวจ API สด 74 จุด, วัน/หน่วย/ค่าว่าง, quota และสิทธิ์; ตรวจ boundary/registry | รายงาน response จริงและ mapping 77 ID ไม่มีซ้ำ/ขาด หรือระบุจุดที่ unavailable ได้ |
| 2 | ขยาย refresh และ map snapshot | แยกแหล่งได้ถูกต้อง; แหล่งใดล่มอีกแหล่งยังใช้งาน; ไม่เผยแพร่เลขปลอม/ข้อมูลเก่า |
| 3 | FastAPI endpoint และ Next.js proxy | ส่ง 77 records พร้อมสถานะ; ตรวจ day; credentials อยู่ server; endpoint เดิมยังทำงาน |
| 4 | SVG map และรายละเอียดจังหวัด | ดูได้ทั้งมือถือ/desktop; วันนี้/พรุ่งนี้ตรง; click/keyboard/selector ใช้ได้; source และชนิดค่าเห็นชัด |
| 5 | ทดสอบและปรับเอกสาร | ทดสอบ source routing 3+74, null/NaN/stale/API ล่ม/โมเดลล่ม, ข้ามเที่ยงคืนไทย, mapping 77; ผ่าน lint/typecheck/build และตรวจ browser จริง |

จุดแก้หลัก: `scripts/refresh_uv_forecast.py`, registry จังหวัด, `backend/services/uv_service.py`, `backend/api/v1/routes/uv.py`, Next.js proxy และหน้า `/uv-map` พร้อม SVG asset; เพิ่ม focused tests ในระบบทดสอบเดิม ไม่สร้าง framework ใหม่

รุ่นแรกไม่เพิ่ม hourly timeline, GPS, ค่าเฉลี่ยเชิงพื้นที่, Redis, ฐานข้อมูลประวัติ UV หรือโมเดล 77 จังหวัด เพิ่มเมื่อมีความต้องการและหลักฐานรองรับ ส่วน hourly/time alignment ทำเมื่อจำเป็นต้องให้ทุกแหล่งมีความหมายตรงกันอย่างเคร่งครัด
